수업 시간에 한 GPIO · 인터럽트 · 타이머/PWM · ADC 실습(1~9)을 끝까지 수행하고, 값을 기록해 보고서로 남긴다. 그리고 종합 실습 9의 램프 컨트롤러를 확장해, 시간에 민감한 동작을 "측정으로 검증"하는 경험을 한다. 수업에서 못 한 실습은 이 과제에서 한다. 여기서 만든 보고서·코드는 이후 센서·카메라 실습에서 계속 쓴다.

## A. 실습 1~9 수행 보고서 (45점)

각 실습마다 **회로 사진 · 실행 캡처 · 아래 기록 항목 · 질문 답**을 넣는다. 실습 1개당 5점 (기록 항목을 다 채우고 질문에 답하면 만점).

| # | 실습 | 기록 항목 | 질문 |
|---|---|---|---|
| 1 | LED (`blink.py`) | 회로 사진 · `gpioinfo` 로 찾은 핀 7의 라인 번호 · blink 실행 캡처 | 저항 값을 330 Ω → 1 kΩ 으로 바꾸면 밝기는? 이유는? |
| 2 | 버튼 (`count_button.py`) | 바운스 이벤트 수(`gpiomon`, 5회 평균) · 디바운스 전/후 카운트 표(10회 누름) · 플로팅 관찰 캡처 | — |
| 3 | 반응속도 게임 (`reaction.py`) | 5라운드 표(최고·평균) · 부정 출발 처리 캡처 | 폴링 버전(`reaction_poll.py`)과 비교 1문단 (반응 시간 · CPU 사용 · 코드 복잡도) |
| 4 | 루프백 지연 (`loopback.py`) | 히스토그램 3개(로그 x축: 무부하 / 부하 / 부하+`chrt`) · 조건별 평균·99%·최대 표 | 왜 평균이 아니라 최대값을 보는가? (2문장) |
| 5 | PWM 디밍 · 서보 (`pwm_led.py` `servo.py`) | 서보 0°·90°·180° 실측 듀티 표 · 5 Hz 깜빡임 영상 또는 캡처 | 듀티 50 %에서 밝기가 절반으로 안 보이는 이유 (2문장) |
| 6 | 트리거 신호 생성기 (`trigger.sh` 외) | 되는 최저 HW PWM 주파수 · 주기 측정 표(HW / SW / SW+chrt / SW+부하 각각 평균·표준편차·최대 편차) · 2채널 위상차(셸 vs Python) | 이 Jetson으로 10 Hz 카메라 트리거를 PPS에 맞추려면 무엇이 더 필요한가? (3문장) |
| 7 | 초음파 주차보조 (`pdc.py`) | 거리 3점(20·50·100 cm) × 20회 산포 표(평균·표준편차) · 줄자 실측과 비교 · 부저 동작 영상 | — |
| 8 | ADS1115 조향 (`steer.py`) | `i2cdetect` 캡처 · 가변저항 양끝·중간 전압과 각도 표 · (선택) 듀티-전압 표와 그래프(`pwm_dac.py`) | ADC 분해능 16비트가 서보 각도에 의미 있는가? (2문장) |
| 9 | 램프 컨트롤러 (`lamp.py`) | 동작 영상(10초) · 주기 측정 표(무부하 / 부하) · 상태 전이도 그림 | → B 부분과 함께 작성 |

### 실습별 메모
- **실습 4·7·8**은 수업 시간에 못 했을 수 있음. 과제에서 수행. (실습 4: `stress-ng -c $(nproc) --timeout 120s &` 를 켠 채로 부하 조건 측정)
- **실습 6**: 10 Hz 가 `Invalid argument` 로 안 되는 장비는 **정상일 수 있음**. 되는 최저 주파수를 기록하고, 이후 단계는 그 주파수로 한다(명목 주기도 그에 맞춰 `--nominal-ms` 수정). 이 경우 "왜 안 되는가"를 `trigger.sh` 가 출력한 설명을 바탕으로 설명한다.
- 측정값은 **본인이 직접 실행**해서 얻은 것만 인정 (조 장비 공유는 OK).
- 표에는 단위(ms, µs, cm, V)를 쓴다. 값 몇 개만 적지 말고 `analyze.py`·`latency_plot.py` 출력을 그대로 붙인다.

## B. 램프 컨트롤러 확장 (40점)

시작점은 `lab6/09_lamp/lamp_skeleton.py` (수업에서 TODO 2곳을 채운 파일). 아래 4가지를 완성해 `lamp.py` 로 제출한다.

| # | 항목 | 요구사항 |
|---|---|---|
| B-1 | 브레이크등 PWM | 핀 15 PWM. 평소 미등 **20 %**, 두 버튼을 **동시에 누르는 동안 100 %**. 동시 누름이 방향지시등/비상등 동작으로 오인되지 않을 것 |
| B-2 | 직접 디바운스 | `add_event_detect` 에 **`bouncetime` 을 주지 않고**, 바운스 에지를 걸러내는 코드를 직접 작성 (예: 마지막 에지 후 일정 시간 지나 안정된 값을 읽기 / 일정 시간 무시). 버튼 1회 = 이벤트 1개임을 로그로 보일 것 |
| B-3 | 주기 측정 로그 200회 | LED L 점멸 200주기를 측정해 `log_period.txt` 로 제출. 무부하 / 부하(`stress-ng`) 두 조건. `analyze.py` 로 평균·표준편차·최대 편차 표를 만든다 |
| B-4 | 상태 전이도 | OFF · LEFT · RIGHT · HAZARD 4상태, 이벤트(L_SHORT · R_SHORT · L_LONG · R_LONG, 동시 누름) 를 화살표로. 손으로 그려 사진도 가능 |

### 기능 요구사항 (기능 20점)
| 항목 | 기준 | 점 |
|---|---|---|
| 방향지시등 상호 배타 | 짧게 L → 좌 점멸 ON/OFF, R → 우 점멸. 한쪽이 켜진 상태에서 반대쪽을 누르면 전환 | 4 |
| 비상등 | 1초 이상 누르면 양쪽 점멸 ON, 다시 길게 누르면 해제 | 4 |
| 브레이크등 PWM | 평소 20 %, 두 버튼 동시 100 % | 4 |
| 직접 디바운스 | `bouncetime` 없이 버튼 1회 = 1 이벤트 | 4 |
| 점멸 주기 | 1.5 Hz ± 5 % (주기 633 ~ 700 ms), 듀티 50 % | 4 |

### 측정·분석 (10점) / 코드 품질 (10점)
| 구분 | 기준 | 점 |
|---|---|---|
| 측정·분석 | 200주기 로그 · 무부하/부하 표(평균·표준편차·최대 편차) · 결과 해석(부하에서 무엇이 달라졌고 왜) | 10 |
| 코드 품질 | 콜백은 큐에 넣기만 · 전이표 dict · 점멸을 `monotonic` 시계로 계산(sleep 누적 없음) · 블로킹 없음 · `try/finally` cleanup · 주석 | 10 |

### 주기 측정 방법
- `lamp.py` 가 핀 7(라인 106)을 점유하므로 `gpiomon gpiochip0 106` 은 `Device or resource busy` 가 난다. 둘 중 하나로 측정:
  1. **`python3 lamp.py --period-log`** → `log_period.txt` (프로그램이 본 시각, 소프트웨어 측정)
  2. **핀 7 → 핀 31 점퍼**를 추가하고 `../06_trigger/measure_period.sh -c 1 -l 0 -n 200 -o lamp.txt` (커널 타임스탬프, 더 정확)
- 점멸 주기 분석은 **한 상태(예: 좌 점멸)를 200주기(약 133초) 유지**한 구간만 의미가 있다. 상태를 바꾸지 말 것.
- `python3 ../06_trigger/analyze.py log_period.txt --nominal-ms 666.7` (두 방법 모두 같은 스크립트로 분석 — 실습 6 폴더의 도구를 `09_lamp/` 에서 상대 경로로 호출)

## 힌트와 자주 하는 실수
**힌트**
- 콜백은 `q.put((핀, 시각))` 한 줄. 판정은 메인 루프에서 (이벤트 큐)
- 시간은 `time.monotonic()` — 시스템 시계가 바뀌어도 안 흔들림
- 상태 전이는 `{(상태, 이벤트): 다음 상태}` dict 표로. `if` 중첩보다 버그가 적음
- 정확한 주기는 `gpiomon` 이 가장 정확 (커널 타임스탬프). 파이썬 `print` 시각은 보조
- 디바운스: "마지막 에지 후 N ms 지나 안정된 값을 읽는다" 가 가장 단순

**자주 하는 실수**
| 실수 | 증상 | 대책 |
|---|---|---|
| 콜백 안에서 `sleep`/`print`/긴 계산 | 이벤트가 밀리거나 놓침 | 큐에 넣고 끝 |
| 점멸을 `sleep(0.333)` 으로 | 시간이 갈수록 주기가 늘어남(누적 드리프트) | `monotonic` 으로 현재 시각에서 상태 계산 |
| `cleanup()` 누락 | 다음 실행에서 `Device or resource busy`, 핀이 켜진 채 남음 | `try/finally` |
| 동시 누름 오판 | 브레이크를 밟으려 했는데 방향지시등이 켜짐 | 두 버튼이 100 ms 안에 눌렸는지 / 둘 다 눌린 상태인지 확인 |
| 트리거 측정 시 핀 7/15 혼동 | 측정 파일이 비어 있음 | HW PWM = 핀 **15**, SW 트리거 = 핀 **7** → 둘 다 핀 22 로 점퍼 |
| `wait_for_edge` 의 timeout 단위 | 시간 초과가 안 일어남 | Jetson.GPIO 는 **초**(정수) 단위 |
| 풀업 없이 버튼 | 값이 떠다님 | 10 kΩ 풀업 (Jetson.GPIO 는 `pull_up_down` 을 무시) |
